<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client (browser) → Server Action | Primeiro endpoint público não-autenticado de write; toda entrada do visitante (e-mail, consentimento) é não-confiável e cruza aqui |
| Server Action → Resend API | Write externo; segredos server-only viajam só no servidor (TLS pelo SDK) |
| Server Action → client island | O contrato `SubscribeState` cruza de volta; NUNCA segredos |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Tampering / Repudiation | consentimento LGPD | mitigate | Consentimento revalidado server-side na action (`formData.get("consent") !== "on"` → consent_error) ANTES de qualquer chamada Resend; checkbox do cliente é só UX (D-08, critério 3). |
| T-05-04 | Input Validation (Tampering) | campo e-mail | mitigate | HTML5 `type="email" required` no cliente + regex server-side (`EMAIL_RE`) com trim/lowercase antes do envio (D-09); SDK envia JSON estruturado, sem interpolação em headers SMTP (sem injeção). |
| T-05-05 | Information Disclosure | `RESEND_API_KEY` no bundle client | mitigate | Segredos lidos SÓ na action (server); nunca `NEXT_PUBLIC_`, nunca importados no client island; grep do componente por `RESEND_*` deve retornar vazio (verificado na Task 2). |
| T-05-06 | Information Disclosure | enumeração de e-mail já inscrito | mitigate | D-11: mesma mensagem de sucesso para novo e existente; resposta idempotente do SDK torna isso o comportamento natural; nunca revela estado prévio. |
| T-05-07 | Information Disclosure | leak de stack/código de erro Resend | mitigate | Todo `{error}` mapeia para um único `server_error` com copy sóbria (UI-SPEC state 6); sem trace, sem código exposto ao visitante; sem log de PII. |
| T-05-08 | Denial of Service / Spoofing | bot/list-stuffing no write público | mitigate | Honeypot hidden field (absorve bot silenciosamente → success) + rate limit nativo do Resend (5 req/s por team). SEM CAPTCHA de terceiro (lei de marca). Throttle per-IP é follow-up aditivo (A4), não bloqueante para v1. |
| T-05-09 | Spoofing (CSRF) | invocação do Server Action | accept | Next.js Server Actions têm origin-check embutido + action ids criptografadas em trânsito (Next 16); sem token CSRF extra necessário — risco residual baixo aceito. |
</threat_model>
