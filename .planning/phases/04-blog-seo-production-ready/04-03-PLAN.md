<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MDX body -> rendered HTML | Article body compiled to React at build; raw HTML/scripts in MDX could execute |
| author/post data -> JSON-LD <script> | Structured-data strings injected into the page |
| clipboard / Web Share -> browser | Client island reads window.location and writes to clipboard |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Elevation/XSS | MDX render (raw HTML in content) | mitigate | Render via next-mdx-remote-client/rsc with NO rehype-raw and components mapped through ProseDino; do not enable raw-HTML passthrough. Content is author-controlled (Phase 4 stubs); Phase 6 generation will pass the same loader. |
| T-04-06 | Information Disclosure/XSS | Article/Person/Org/Breadcrumb JSON-LD | mitigate | All JSON-LD emitted through <JsonLd> which applies .replace(/</g,"\\u003c") (Wave-2 primitive). No hand-serialized script tags in the route. |
| T-04-07 | Tampering | canonical/OG/@id URL composition | mitigate | All absolute URLs derive from SITE_URL (build-time env, not user input); slug comes from the filesystem enumeration, not request body. |
| T-04-08 | DoS | unknown slug handling | accept | SSG enumerates known slugs; unknown -> notFound() 404. No runtime fetch amplification. |
</threat_model>
